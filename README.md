# 校园健康引导小程序（Campus Health Guide）

## 一、项目概述

### 1.1 这是什么

**校园健康引导小程序**是一个面向在校大学生的微信小程序项目，旨在通过数字化手段引导大学生建立健康的生活习惯。项目以"轻量、无感、正向激励"为设计原则，覆盖步数打卡、饮食记录、运动计划推荐、心理自评四大核心模块。

本项目为**大学生创新创业训练计划（大创）项目**，项目周期 28 周（2026 年 10 月至 2027 年 5 月），由 8 人学生团队从零开始完成需求分析、设计、开发、测试、部署及结题全流程。

### 1.2 项目目的

| 维度 | 目标 |
|---|---|
| 用户价值 | 帮助大学生养成每日步数达标、合理饮食、规律运动、关注心理健康的习惯 |
| 产品目标 | 交付一个可运行、可演示、可实际使用的微信小程序 |
| 学术目标 | 完成大创结题要求（软件著作权 / 结题报告 / 答辩） |
| 团队目标 | 8 人团队通过真实项目实践，掌握协作开发、项目管理、产品交付全流程 |

### 1.3 基于什么开发

| 层次 | 技术选型 | 说明 |
|---|---|---|
| 前端 | 微信小程序原生框架（WXML + WXSS + JavaScript） | 不依赖第三方框架，降低维护成本 |
| 后端 | Python 3.15 + FastAPI | 轻量异步框架，适合小团队快速迭代 |
| 算法模块 | C++ 26 | 运动计划生成引擎、心理量表算分逻辑 |
| 算法桥接 | pybind11 | C++ 模块编译为 Python 扩展，供后端调用 |
| 数据库 | MySQL 8.0 | 业务数据存储 |
| 缓存 | Redis 7 | 会话管理、步数缓存、接口限流 |
| 评测沙箱 | Docker + GitHub Actions CI | 自动化单测、集成测试、覆盖率检查 |
| 代码托管 | AtomGit | Git 版本控制 + PR 协作 |
| 知识管理 | 飞书 | 文档、任务看板、会议纪要 |
| 部署环境 | 腾讯云轻量应用服务器（2C4G） | 学生优惠，满足 50–200 并发 |

## 二、项目规则

### 2.1 分支策略

| 分支 | 用途 | 保护规则 |
|---|---|---|
| `main` | 生产基线，随时可演示、可结题 | 禁止直推，仅接受 PR 合并，需 CI 通过 + 1 人评审 |
| `testing` | 集成测试，各模块合入后联调 | 禁止 force push，允许 ③ 直接推送 |
| `dev/*` | 功能开发，命名格式 `dev/模块-日期-负责人` | 无保护，合入 testing 后删除 |
| `hotfix/*` | 紧急修复，命名格式 `hotfix/描述-日期` | 合入 main 需项目负责人审批 |

### 2.2 提交信息规范

所有提交信息必须遵循以下格式：

```plaintext
<type>(<scope>): <subject>
```

| type | 含义 |
|---|---|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档变更 |
| `style` | 代码格式调整（不影响逻辑） |
| `refactor` | 重构 |
| `test` | 测试相关 |
| `chore` | 构建/依赖/工具变更 |

示例：

```plaintext
feat(step): 实现步数双路采集（微信运动 + 手动录入）
fix(auth): 修复 token 过期后未自动刷新问题
docs(readme): 更新 README 项目规则章节
```

### 2.3 代码风格

**本项目所有代码必须采用 Allman 风格（花括号独占一行，同级对齐），缩进 4 空格。**

详细代码风格要求见知识库文档：`00-文档风格规范`。

### 2.4 文档规范

- 所有知识库文档使用 Markdown 格式
- 文件命名：`[模块]_[类型]_[YYYYMMDD]_[负责人].md`
- 每篇文档顶部包含元数据表格（版本、日期、作者、状态）
- 标题不跳级，编号连续
- 代码块必须标注语言类型

### 2.5 评审规则

- 所有 `feature/*` → `testing` 的 PR 必须经过至少 1 人评审
- 所有 `testing` → `main` 的合并由项目负责人或 ③ 审批
- PR 描述必须包含：模块说明、变更内容、自测结果、关联任务编号
- CI 评测未通过（单测失败 / 覆盖率不达标）禁止合并

### 2.6 周会制度

- 时间：每周日晚 20:00
- 时长：15–30 分钟
- 内容：本周完成 / 下周计划 / 卡点当场拍板
- 记录：⑧ 产出 `MEET_NOTE_` 文档

## 四、贡献方案

### 4.1 谁能贡献

本项目为**封闭式大创团队项目**，当前仅限团队成员（8 人）进行代码和文档贡献。

### 4.2 如何贡献（团队成员）

1. **领取任务**：从飞书多维表格「项目任务总表」中选择 `待开始` 状态的任务
2. **创建分支**：从 `testing` 拉取 `feature/[模块]-[日期]-[负责人]` 分支
3. **开发自测**：编写代码，本地运行 `./eval.sh` 评测全绿
4. **提交推送**：按提交信息规范 commit，push 到 AtomGit
5. **创建 PR**：网页端创建 Pull Request，目标分支选 `testing`，指定评审人
6. **评审合并**：评审人通过后在 AtomGit 网页点击合并
7. **清理分支**：合入后删除远程 feature 分支

### 4.3 外部贡献者

**接受外部 Pull Request**，但仅接受 `dev/*` 分支的 PR。且要详细说明你的贡献内容及关联任务编号。

### 4.4 新人上手

新加入成员（或下学期接手团队）按以下顺序阅读：

1. README.md（本文档）

## 五、安全声明：禁止注入危险代码

### 5.1 原则

**本项目严格禁止任何人在代码库中以任何形式注入危险代码。**

### 5.2 定义

以下行为均被认定为"注入危险代码"：

| 类别 | 具体行为 |
|---|---|
| 恶意逻辑 | 删除文件、格式化磁盘、破坏系统（`rm -rf /`、fork 炸弹等） |
| 后门 | 预留未授权访问入口、硬编码管理员凭证、隐藏 API 端点 |
| 数据泄露 | 将用户数据（openid、步数、测评结果）发送至外部服务器 |
| 依赖投毒 | 引入未审计的第三方依赖、使用已知存在漏洞的库版本 |
| 令牌泄露 | 将 API Key、数据库密码、SSL 证书等硬编码在源码中 |
| 混淆代码 | 故意使用混淆/加密代码隐藏逻辑，阻碍代码审查 |
| 环境破坏 | 在构建脚本/评测脚本中植入修改宿主机环境的命令 |

### 5.3 检测与防范

| 手段 | 说明 |
|---|---|
| 强制 PR 评审 | 所有代码合入前至少 1 人审查 |
| CI 静态检查 | 评测流水线包含依赖漏洞扫描 |
| 沙箱隔离 | 评测环境 `--network none` + 资源限制，防止外联和滥用 |
| 敏感信息扫描 | 提交前检查是否包含密钥模式（正则匹配） |
| main 分支保护 | 禁止直推，防止绕过审查 |

### 5.4 违规后果

| 程度 | 处理 |
|---|---|
| 无意引入（如误提交测试密钥） | 立即撤回，重新提交，记录教育 |
| 故意注入危险逻辑 | **立即移出项目**，上报导师和学院，记入结题贡献评估 |
| 外部人员发现漏洞 | 通过正规渠道报告，不追责，感谢并修复 |

> 🔴 **本项目对代码安全采取零容忍态度。任何试图绕过评审、在沙箱外执行未授权操作的行为，一经发现，立即终止其参与资格。**

## 六、注意事项

### 6.1 开发环境

| 项目 | 要求 | 推荐 |
|---|---|---|
| 操作系统 | Linux / Windows（WSL2 推荐） | Ubuntu 26.04 / Windows 11 |
| Node.js | ≥ 18.0（前端构建） | Node.js 20.16.0 |
| Python | > 3.14.0 | 3.15.0 |
| C++ 编译器 | g++ 20+ / Clang 20+ | g++ 16.2.0 |
| Docker | ≥ 24.0（评测沙箱） | Docker 24.0.0 |
| 微信开发者工具 | 最新稳定版 | 最新稳定版 |
| Git | ≥ 2.43 | Git 2.56.0 |

### 6.2 微信小程序相关

- 微信小程序 AppID 由项目负责人统一管理，不对外公开
- 微信步数数据获取需用户授权 `scope.werun`，授权拒绝时降级为手动录入
- 小程序类目选择"工具 > 健康管理"，**不涉及医疗诊断**（不触碰在线问诊类目）
- 心理测评模块仅提供自评量表（PHQ-9 / GAD-7 / 睡眠自评），所有结果标注"仅供参考，不作诊断"

### 6.3 数据安全与隐私

- 不收集用户真实姓名、身份证号、手机号（微信 openid 为唯一标识）
- 心理测评结果服务端加密存储，仅用户本人可查看
- 所有接口强制鉴权（JWT），SQL 层加 `WHERE openid = ?` 防越权
- 服务器定期自动备份数据库（每日），每周验证一次恢复流程

### 6.4 法律合规

| 事项 | 状态 |
|---|---|
| 软件著作权 | 计划申请（W18 提交） |
| 量表使用授权 | PHQ-9 / GAD-7 为公共领域工具，无需授权；使用注明出处 |
| 隐私政策 | 小程序上线前必须配置隐私政策页面 |
| 用户协议 | 随隐私政策一并配置 |
| 开源协议 | 结题前确定（暂定 Apache 2.0 或 MIT） |

### 6.5 降级方案（时间不够时）

| 优先级 | 模块 | 降级策略 |
|---|---|---|
| P0（保死） | 步数打卡 + 热量统计 + 运动周计划 + 心理量表 | 不可砍 |
| P1 | 饮食拍照 OCR | 降级为文字搜索 |
| P2 | 运动动作视频 | 降级为图文步骤 |
| P3 | 心理社交打卡 | 直接删除 |
| P3 | 数据可视化周报 | 降级为纯数字展示 |

### 6.6 常见问题

| 问题 | 回答 |
|---|---|
| 为什么不用 Java / Go？ | 团队仅具备 C++ 和少量 Python 基础，现学成本过高 |
| 为什么 C++ 只做算法？ | C++ 写接口和数据库对团队门槛太高，Python 桥接是性价比最优解 |
| 为什么不用 uni-app？ | 原生框架学习成本低，调试方便，团队 8 人无人会 Vue |
| 服务器多少钱？ | 腾讯云轻量 2C4G 约 ¥60/月，学生认证可打折，总预算 ¥800–1000 |
| 结题要什么？ | 以本校大创结题条件为准，当前对齐：可运行软件 + 软著 + 结题报告 + 答辩 |
