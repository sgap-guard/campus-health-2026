## 一、适用范围

本规范适用于本项目中**所有 Markdown 文档**，包括但不限于：

- 需求文档、设计文档、技术文档
- 接口文档、数据库设计、部署手册
- 会议纪要、周报、测试报告
- 用户手册、结题材料、答辩材料

**所有项目成员在创建或编辑任何知识库文档时，必须严格遵守本规范。**

## 三、标题层级规范

### 3.1 层级规则

| 层级 | 语法 | 用途 | 出现位置 |
|---|---|---|---|
| 一级 | `# 标题` | 文档标题（唯一） | 文档最顶部，仅 1 个 |
| 二级 | `## 标题` | 章 | 顶级分区 |
| 三级 | `### 标题` | 节 | 章内子主题 |
| 四级 | `#### 标题` | 子节 | 节内细分 |
| 五级 | `##### 标题` | 最小单元 | 仅用于列表项下的说明 |
| 六级 | `###### 标题` | 极细粒度 | 原则上禁止使用 |

### 3.2 强制要求

1. **一级标题仅允许出现 1 次**，位于文档第一行（或 YAML 前置元数据之后）
2. **禁止跳级**：`#` → `##` → `###` → `####`，不得从 `##` 直接跳到 `####`
3. **每个二级标题下必须有正文或三级标题**，禁止空章
4. **标题末尾不加标点**（问号、感叹号除外）
5. **标题中不使用粗体**，标题本身已加粗

### 3.3 标题命名风格

- 章标题（二级）：名词短语或简短动宾结构
  - ✅ `## 三、接口设计`
  - ✅ `## 四、数据库表结构`
  - ❌ `## 3` （缺少描述）
  - ❌ `## 关于接口的一些设计想法` （过于口语化）
- 节标题（三级）：具体描述内容
  - ✅ `### 3.1 步数采集接口`
  - ✅ `### 3.2 错误码定义`
- 子节标题（四级）：操作级或属性级
  - ✅ `#### 3.2.1 请求参数`
  - ✅ `#### 3.2.2 响应示例`

### 3.4 标题编号

- 二级标题采用中文数字编号：`## 一、xxx`、`## 二、xxx`
- 三级标题采用 `x.y` 数字编号：`### 2.1 xxx`、`### 2.2 xxx`
- 四级标题采用 `x.y.z` 数字编号：`#### 2.2.1 xxx`
- 编号在文档内连续，不跨文档延续

## 四、正文格式规范

### 4.1 段落

- 段落之间**空一行**分隔
- 段落内不手动换行（不按 Enter 制造短行）
- 每段聚焦一个观点，长度控制在 3–8 句

### 4.2 字体样式

| 用途 | 语法 | 示例 |
|---|---|---|
| 强调 | `**加粗**` | **关键结论** |
| 代码引用（行内） | `` `代码` `` | `wx.login()` |
| 文件路径 | `` `路径` `` | `miniprogram/pages/index/` |
| 术语首次出现 | `**术语**（解释）` | **JWT**（JSON Web Token） |
| 删除/废弃 | `~~删除线~~` | ~~旧方案~~ |
| 斜体 | `*斜体*` | 仅用于外文短语 |

### 4.3 列表

#### 无序列表

- 使用 `-` 作为标记
- 同级左对齐
- 子列表缩进 2 个空格
- 列表项末尾不加标点（除非是完整句子）

```markdown
- 第一项
- 第二项
  - 子项 A
  - 子项 B
- 第三项
```

#### 有序列表

- 使用 `1.` 编号
- 子列表缩进 2 个空格

```markdown
1. 第一步
2. 第二步
   - 注意点 A
   - 注意点 B
3. 第三步
```

### 4.4 表格

- 表头必须有
- 表格上方加一行说明文字（可选但推荐）
- 列对齐：文字左对齐，数字右对齐

```markdown
| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `openid` | `string` | 是 | 微信用户唯一标识 |
| `steps` | `int` | 是 | 步数，范围 0–100000 |
| `date` | `date` | 是 | 记录日期，格式 `YYYY-MM-DD` |
```

### 4.5 链接

- 外部链接使用描述性文字，不使用裸 URL

✅ 详见 [微信小程序 API 文档](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/werun/wx.getWeRunData.html)

❌ 详见 https://developers.weixin.qq.com/...

- 内部文档链接使用相对路径或文件名

```markdown
详见 [饮食接口文档](./DIET_API_20261115_成员4.md)
```

## 五、代码块规范

### 5.1 通用规则

- 所有代码块必须标注语言类型
- 代码块前后各空一行
- 代码块内不使用 Markdown 语法
- 代码块内添加必要注释（关键逻辑必加）

### 5.2 语言标注

```markdown
✅ ```cpp
✅ ```python
✅ ```javascript
✅ ```sql
✅ ```bash
✅ ```dockerfile
✅ ```yaml
✅ ```json

❌ ```
```

### 5.3 代码风格：Allman 风格（强制）

**所有代码块、配置片段、SQL 语句、脚本文件均必须采用 Allman 风格。**

#### 核心规则

| 规则 | 说明 |
|---|---|
| 花括号 `{}` 独占一行 | 不跟在语句末尾 |
| 同级花括号对齐 | 左 `{` 和右 `}` 在同一列 |
| 内部代码缩进 | 4 个空格（不使用 Tab） |
| 控制语句必须加大括号 | 即使只有一行，也不省略 `{}` |
| 括号两侧加空格 | `if (condition)` 而非 `if(condition)` |
| 运算符两侧加空格 | `a = b + c` 而非 `a=b+c` |
| 逗号后加空格 | `func(a, b, c)` 而非 `func(a,b,c)` |
| 每行不超过 100 字符 | 超长则换行，换行后对齐 |

#### C++ 示例

```cpp
#include <iostream>
#include <vector>

int CalculateCalories(int steps, double weightKg)
{
    if (steps <= 0)
    {
        return 0;
    }
    
    const int BASE_CALORIES_PER_STEP = 0.04;
    double calories = steps * BASE_CALORIES_PER_STEP * (weightKg / 60.0);
    
    return static_cast<int>(calories);
}

class StepCounter
{
public:
    StepCounter(int initialSteps)
        : m_steps(initialSteps)
    {
    }
    
    void AddSteps(int delta)
    {
        if (delta > 0)
        {
            m_steps += delta;
        }
    }
    
    int GetSteps() const
    {
        return m_steps;
    }

private:
    int m_steps;
};
```

def calculate_bmi(weight_kg, height_m):
    if height_m <= 0:
        raise ValueError("Height must be positive")
    
    bmi = weight_kg / (height_m ** 2)
    
    if bmi < 18.5:
        return "underweight", bmi
    elif bmi < 24.0:
        return "normal", bmi
    else:
        return "overweight", bmi


class DietRecord:

## 九、文档生命周期管理

### 9.1 创建

1. 在对应开发分支`dev`下创建新文件
2. 按命名规范命名文件
3. 填入元数据表格
4. 状态设为 `草稿`

### 9.2 评审

1. 作者完成初稿后，状态改为 `评审中`
2. 提交Pull Request（PR），附文档链接
3. 评审人 24 小时内给出反馈（文档内评论或群内回复）
4. 作者根据反馈修改

### 9.3 定稿

1. 评审通过，状态改为 `已定稿`
2. 版本号更新（如 `v1.0`）
3. 内容冻结，后续改动走新版本
4. 提交到主分支`main`
